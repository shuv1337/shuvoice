# ShuVoice integration: automatic media pause during recording

## 1. Where exactly does recording begin and end today?

### Takeaway

**Code verified:** PTT acceptance, successful ASR reset, microphone capture, key-up, capture-tail completion, and transcript completion are different boundaries. Pause ownership belongs in the session lifecycle; resuming directly on key-up can put media audio into the utterance's still-open tail.

### Cited Findings

- **Control entry / acknowledgment:** `EnqueueControlAdapter::on_serialized_command` routes `start`, `toggle`, `start_alt`, and `toggle_alt` through an actor `ControlRequest`, with a 400 ms acknowledgment wait. `on_stop` enqueues `Stop`. `handle_command` returns `OK started` after requesting start, even if an internal gate ignored it; that string is not proof recording began. Maintenance blocks start/toggle before dispatch. — [runtime.rs:91–139](../../crates/shuvoice-app/src/runtime.rs#L91-L139), [session.rs:2389–2490](../../crates/shuvoice-app/src/session.rs#L2389-L2490)
- **Accepted start:** `request_start_recording_with_case` first stops active ShuVoice TTS, then checks ASR liveness, duplicate pending/recording, and the start gate. Rearm is 350 ms **only while processing**. Both admitted branches capture preroll, set `start_pending=true`, `processing=true`, and spawn a lifecycle reset; disabled recovery performs a recovery reset followed by the normal start reset. Rejected start must not acquire an external-media lease. — [session.rs:685–762](../../crates/shuvoice-app/src/session.rs#L685-L762), [core runtime:62–92](../../crates/shuvoice-core/src/runtime/mod.rs#L62-L92), [circuit_breaker.rs:125–129](../../crates/shuvoice-core/src/circuit_breaker.rs#L125-L129), [session.rs:1395–1435](../../crates/shuvoice-app/src/session.rs#L1395-L1435)
- **Started:** successful start reset calls `complete_start_recording(g)`: assigns ASR generation, captures preroll again, clears pending/processing, sets recording, resets injection, records metrics, shows Listening, emits Recording, and optionally plays the start tone. The subsequent tick calls `begin_utterance` on the rising edge and appends PCM. — [session.rs:810–834](../../crates/shuvoice-app/src/session.rs#L810-L834), [session.rs:901–937](../../crates/shuvoice-app/src/session.rs#L901-L937), [session.rs:1884–1927](../../crates/shuvoice-app/src/session.rs#L1884-L1927)
- **Physical capture is continuous:** composition starts an `AudioBridge` after runtime creation and before the control server. Its OS-thread loop forwards microphone chunks regardless of session recording state. PTT stop does not stop CPAL. There are backend and app queues; CPAL also assembles pending samples into fixed chunks. The app ring stores un-timestamped `Vec<f32>` chunks. — [compose/mod.rs:930–1009](../../crates/shuvoice-cli/src/compose/mod.rs#L930-L1009), [audio_bridge.rs:17–29](../../crates/shuvoice-cli/src/compose/audio_bridge.rs#L17-L29), [audio_bridge.rs:495–509](../../crates/shuvoice-cli/src/compose/audio_bridge.rs#L495-L509), [cpal_source.rs:215–274](../../crates/shuvoice-io/src/audio/cpal_source.rs#L215-L274), [app/audio.rs:17–25](../../crates/shuvoice-app/src/audio.rs#L17-L25)
- **Preroll:** `capture_recording_preroll` drains the ring and combines it with retained preroll, selecting up to configured samples; default `recording_preroll_ms` is 200. Idle ticks otherwise use drained PCM for noise-floor updates; this is not a timestamped continuous preroll buffer. — [session.rs:901–907](../../crates/shuvoice-app/src/session.rs#L901-L907), [session.rs:1857–1900](../../crates/shuvoice-app/src/session.rs#L1857-L1900), [config/model.rs:204](../../crates/shuvoice-core/src/config/model.rs#L204)
- **Pending-start cancellation:** stop clears `start_pending`, aborts the lifecycle task, clears processing, and returns if not recording. A later reset result is ignored when `start_pending` is false. No `last_stop_at` is set on this branch, so rapid pending-start stop/start does not receive the normal rearm protection. — [session.rs:850–882](../../crates/shuvoice-app/src/session.rs#L850-L882), [session.rs:1395–1435](../../crates/shuvoice-app/src/session.rs#L1395-L1435)
- **Normal stop:** stop clears recording, sets processing, timestamps stop, updates metrics, plays optional stop tone, and publishes Processing. It does not start finalization inline. Tick detects `was_recording && !recording`; it continues buffering audio while waiting for an outstanding chunk job, then starts finalize. — [session.rs:850–882](../../crates/shuvoice-app/src/session.rs#L850-L882), [session.rs:1889–1944](../../crates/shuvoice-app/src/session.rs#L1889-L1944)
- **Tail / finalize:** `start_finalize_job` drains the ring, moves utterance state into a job, and creates a late-audio channel. Actor-side forwarding remains open for `STOP_TAIL_GRACE=120 ms` from finalize start. The child has its own Tokio-time grace deadline, absorbs queued late chunks, then checks cancellation/generation, silence, and mode (offline, remote manual commit, local streaming). Local tail flush uses synthesized noise, not additional microphone capture. The two deadlines are not one explicit capture-closed handshake. — [session.rs:941–983](../../crates/shuvoice-app/src/session.rs#L941-L983), [session.rs:1227–1238](../../crates/shuvoice-app/src/session.rs#L1227-L1238), [session.rs:1864–1883](../../crates/shuvoice-app/src/session.rs#L1864-L1883), [finalize.rs:106–202](../../crates/shuvoice-app/src/finalize.rs#L106-L202), [finalize.rs:343–385](../../crates/shuvoice-app/src/finalize.rs#L343-L385), [core runtime:109–110](../../crates/shuvoice-core/src/runtime/mod.rs#L109-L110)
- **Finalize result / injection:** stale finalize jobs are rejected against the tracked generation. Silent, Ready/Committed, Cancelled, and Failed all converge on state/status cleanup; a final injection may keep processing true afterward. Therefore idle or transcript commit is later than capture completion and is not the desired normal media-release boundary. — [session.rs:1284–1393](../../crates/shuvoice-app/src/session.rs#L1284-L1393)
- **Cancel/restart:** admitted start during prior finalize/processing invokes `cancel_finalize_and_reset_injector`: flags/aborts finalize, bumps ASR generation if a finalize existed, aborts chunk, clears old state, requests injector reset. TTS finalize timeout and the direct finalize wait timeout also use this helper. There is no separate recording-cancel command in this inspected command dispatch; stop, superseding start, timeout, failure, and shutdown are distinct cancellation routes. — [session.rs:731–752](../../crates/shuvoice-app/src/session.rs#L731-L752), [session.rs:985–1002](../../crates/shuvoice-app/src/session.rs#L985-L1002), [session.rs:1185–1224](../../crates/shuvoice-app/src/session.rs#L1185-L1224), [session.rs:2070–2096](../../crates/shuvoice-app/src/session.rs#L2070-L2096), [session.rs:2466–2499](../../crates/shuvoice-app/src/session.rs#L2466-L2499)
- **Error exits:** normal start-reset failure clears pending/processing; disabled-recovery failure has its own cleanup branch. Circuit opening directly sets recording false. Tick noticing ASR owner death also directly sets recording false. These bypass `stop_recording`; a media hook only there leaks ownership. Nonterminal chunk failures can schedule ASR recovery without ending recording, so releasing on every error is also wrong. — [session.rs:585–626](../../crates/shuvoice-app/src/session.rs#L585-L626), [session.rs:836–848](../../crates/shuvoice-app/src/session.rs#L836-L848), [session.rs:1264–1280](../../crates/shuvoice-app/src/session.rs#L1264-L1280), [session.rs:1429–1435](../../crates/shuvoice-app/src/session.rs#L1429-L1435), [session.rs:1846–1855](../../crates/shuvoice-app/src/session.rs#L1846-L1855)
- **TTS handoff:** request TTS stops active/pending STT, possibly starts finalize immediately, waits for finalize/injection or a deadline, and proceeds. Direct `tts_prepare` similarly stops and pumps. STT-start stops ShuVoice's own TTS rather than arranging its later resumption. — [session.rs:686–692](../../crates/shuvoice-app/src/session.rs#L686-L692), [session.rs:2030–2055](../../crates/shuvoice-app/src/session.rs#L2030-L2055), [session.rs:2070–2096](../../crates/shuvoice-app/src/session.rs#L2070-L2096), [session.rs:2127–2149](../../crates/shuvoice-app/src/session.rs#L2127-L2149)
- **Shutdown:** `Session::shutdown` clears lifecycle flags, aborts lifecycle/finalize/chunk, bumps generation, detaches non-cancellable inject effects, stops TTS, and requests ASR shutdown. Runtime teardown independently requests ASR shutdown, allows the actor 2 seconds, aborts it if needed, aborts dispatcher, and joins ASR with a 5-second bound. Composition stops control, then audio ingress, then runtime; startup failures after runtime creation also use ordered cleanup. — [session.rs:1963–1997](../../crates/shuvoice-app/src/session.rs#L1963-L1997), [runtime.rs:276–340](../../crates/shuvoice-app/src/runtime.rs#L276-L340), [compose/mod.rs:766–807](../../crates/shuvoice-cli/src/compose/mod.rs#L766-L807), [compose/mod.rs:1236–1279](../../crates/shuvoice-cli/src/compose/mod.rs#L1236-L1279)
- **Capture failure limitation:** runtime CPAL errors are logged by `err_fn`; the bridge's capture interface returns `Option<Vec<f32>>`, and its loop keeps polling until its stop flag. These inspected paths do not deliver a typed capture-fatal event to the session. — [cpal_source.rs:220–274](../../crates/shuvoice-io/src/audio/cpal_source.rs#L220-L274), [audio_bridge.rs:199–205](../../crates/shuvoice-cli/src/compose/audio_bridge.rs#L199-L205), [audio_bridge.rs:495–509](../../crates/shuvoice-cli/src/compose/audio_bridge.rs#L495-L509)

### Inferences

- **Integration risk:** successful reset followed by stop before the first recording tick leaves `was_recording=false`; the normal falling-edge finalize path is not armed. A media lease must release independently of receiving a finalize result. This is a source-derived edge case, not a reproduced bug. — [session.rs:810–817](../../crates/shuvoice-app/src/session.rs#L810-L817), [session.rs:1929–1944](../../crates/shuvoice-app/src/session.rs#L1929-L1944)
- A fixed `stop + 120 ms` resume timer is unsafe: an in-flight chunk can delay finalize creation, after which the actual 120 ms grace begins. — [session.rs:1929–1941](../../crates/shuvoice-app/src/session.rs#L1929-L1941), [session.rs:979](../../crates/shuvoice-app/src/session.rs#L979)

### Gaps

- No playback, service, or build/test commands were run. These are source-inspection findings, not verified runtime behavior.
- Audio-device-loss recovery is not fully designed here; an explicit fatal-capture signal would be additional scope if automatic release on device failure is required.

## 2. Which architecture and dependency seams should implement it?

### Takeaway

**Proposal:** introduce a session-owned recording intent/lease and a separately owned asynchronous media coordinator, with the platform adapter in `shuvoice-io` and composition/lifetime wiring in CLI/runtime. Use explicit desired-state reconciliation, not observer events or independent fire-and-forget pause/play tasks.

### Cited Findings

- Existing app effect seams are async `TextInjector`/`SelectionCapture`, synchronous enqueue-style `FeedbackSink`, and an optional transcript sink in `SessionDeps`; there is no external-media seam among these traits. `SessionDeps` supports builder-style optional attachments. — [traits.rs:10–62](../../crates/shuvoice-app/src/traits.rs#L10-L62), [session.rs:60–120](../../crates/shuvoice-app/src/session.rs#L60-L120)
- The actor runs a biased command select and 10 ms tick; long ASR work is already moved to child tasks. A bus call awaited inside `handle_command`, `tick`, or a synchronous feedback method would delay control handling. — [runtime.rs:456–507](../../crates/shuvoice-app/src/runtime.rs#L456-L507), [session.rs:4–14](../../crates/shuvoice-app/src/session.rs#L4-L14)
- Status events are replaceable/coalesced and can be evicted under overflow; event dispatch also depends on an observer draining its receiver. Thus `Status(Recording)`/`Status(Processing)` observation cannot be an exactly-once ownership protocol. — [events.rs:16–28](../../crates/shuvoice-app/src/events.rs#L16-L28), [events.rs:102–122](../../crates/shuvoice-app/src/events.rs#L102-L122), [events.rs:271–333](../../crates/shuvoice-app/src/events.rs#L271-L333)
- ASR generation is allocated by `AsrOwnerHandle::reset`, not at accepted user intent, and error-recovery resets can change `utterance_gen`. Reset results contain a purpose and result generation, but the session matches tracking by purpose discriminant and tests only `start_pending` before accepting start completion. — [asr_owner.rs:140–160](../../crates/shuvoice-app/src/asr_owner.rs#L140-L160), [finalize.rs:24–51](../../crates/shuvoice-app/src/finalize.rs#L24-L51), [session.rs:1395–1456](../../crates/shuvoice-app/src/session.rs#L1395-L1456)
- The code explicitly treats injection side effects as non-cancellable: dropping/aborting a waiter cannot prove an external effect did not occur. This is an existing architectural precedent for retaining side-effect ownership across cancellation. — [session.rs:985–1029](../../crates/shuvoice-app/src/session.rs#L985-L1029), [asr_owner.rs:14–27](../../crates/shuvoice-app/src/asr_owner.rs#L14-L27)
- Dependency evidence: workspace uses Rust 1.92/edition 2024, Tokio with process/sync/time/runtime, and `gio`/`glib` 0.22. `shuvoice-io` already depends on Tokio but not GIO. GIO is currently optional under the UI GTK feature. A scoped search of the manifests/lockfile found no `zbus`, `dbus`, `mpris`, or `playerctl` dependency entry. — [Cargo.toml:16–70](../../Cargo.toml#L16-L70), [io/Cargo.toml:19–29](../../crates/shuvoice-io/Cargo.toml#L19-L29), [ui/Cargo.toml:11–25](../../crates/shuvoice-ui/Cargo.toml#L11-L25), [Cargo.lock](../../Cargo.lock)
- Config/defaults/validation belong to Rust core, settings UI delegates to Rust, and new keys require configuration docs/examples/tests. Runtime no-default-features compatibility is an explicit repository contract. — [AGENTS.md](../../AGENTS.md)

### Inferences

All items below are **proposals**, not present implementation or externally verified D-Bus guarantees.

1. **Dependency choice:** prefer evaluating native async `zbus` for a Tokio-compatible session-bus adapter in `shuvoice-io`, behind an explicit feature if needed. Verify its selected version/MSRV/features before adding it. Existing GIO D-Bus APIs are a second native candidate, but adopting them here should not drag GTK/main-context coupling into headless app logic. `dbus`/`dbus-tokio` are additional candidates, not established dependencies. A `playerctl` subprocess adapter would fit existing Tokio-process availability but adds executable detection and process/result ownership complexity. Do not install or require playerctl merely to implement a native adapter. — Basis: [Cargo.toml](../../Cargo.toml), [io/Cargo.toml](../../crates/shuvoice-io/Cargo.toml), [ui/Cargo.toml](../../crates/shuvoice-ui/Cargo.toml)
2. **Intent token:** allocate a separate monotonic recording-intent epoch at an admitted start, covering recovery, reset, pause acquisition, capture, and tail. Thread that token through *both* media and start-reset completion messages; reject stale completions by token, not just `start_pending` or ASR generation. The old queued reset completion / stop / new accepted start ordering deserves a regression test before extending the existing pending-start state machine. — Basis: [session.rs:1395–1435](../../crates/shuvoice-app/src/session.rs#L1395-L1435), [asr_owner.rs:154–160](../../crates/shuvoice-app/src/asr_owner.rs#L154-L160)
3. **Pause as an owned side effect:** session sends current desired hold state through a nonblocking, loss-resistant channel/state slot; a dedicated coordinator owns every player operation and lease ledger. A bounded `try_send` with ignored full errors is insufficient. A watch/latest-intent design can coalesce obsolete requests, but cannot discard ownership of operations already dispatched. Keep operation IDs and owner identity separately from the latest desired epoch. — Basis: [events.rs:16–28](../../crates/shuvoice-app/src/events.rs#L16-L28), [session.rs:985–1029](../../crates/shuvoice-app/src/session.rs#L985-L1029)
4. **Bounded start gate:** acquire pause after admission, concurrently with ASR reset; keep actor responsive while pending. Complete Listening only when reset is ready and pause acquisition has settled or reached a short explicit global budget. Fail-open for recording on absent/unavailable media control; report bounded, payload-free degradation. Do not count media failure against the ASR breaker or map it to dependency exit 78. The budget is a product latency decision, not a measured constant from this investigation. — Basis: [session.rs:731–761](../../crates/shuvoice-app/src/session.rs#L731-L761), [runtime.rs:456–507](../../crates/shuvoice-app/src/runtime.rs#L456-L507), [AGENTS.md](../../AGENTS.md)
5. **Preroll policy is mandatory:** a pause acknowledgment cannot sanitize pre-pause samples already buffered. Merely calling `audio.clear()` also misses backend hold queues and a partially assembled CPAL chunk. For a first bounded scope, document pause as best-effort contamination reduction and explicitly decide whether to discard retained preroll when the feature is enabled. For a strict clean-audio guarantee, add capture timestamps/sequence fences across backend and app buffering, trim/discard samples before a confirmed boundary, and accept the cost of potentially clipping speech begun before readiness. Do not claim strict silence based solely on a remote method success. — Basis: [session.rs:901–907](../../crates/shuvoice-app/src/session.rs#L901-L907), [audio_bridge.rs:17–29](../../crates/shuvoice-cli/src/compose/audio_bridge.rs#L17-L29), [cpal_source.rs:255–269](../../crates/shuvoice-io/src/audio/cpal_source.rs#L255-L269)
6. **Capture-closed release:** introduce an explicit capture-tail-closed transition for the intent. Release when no more microphone samples can enter that utterance, not on Processing, key-up, final transcript, or injection completion. Ideally let actor close/drop its late sender after the grace boundary and make finalize drain through this authoritative closure; cancellation/failure closes immediately when discarding audio. Ensure the no-first-tick short-tap case also terminates the hold. This refactors the existing pair of independent grace deadlines and needs lossless-tail regression coverage. — Basis: [session.rs:941–983](../../crates/shuvoice-app/src/session.rs#L941-L983), [session.rs:1864–1944](../../crates/shuvoice-app/src/session.rs#L1864-L1944), [finalize.rs:119–148](../../crates/shuvoice-app/src/finalize.rs#L119-L148)
7. **Rapid stop/start:** a late successful pause for A remains an owned effect even when A is obsolete. With no newer hold, compensate it via bounded, identity-checked release; with active B, transfer/retain the hold rather than resuming A into B's recording. A queued resume must recheck latest desired state immediately before dispatch. If resume is already sent, B must wait for settlement/re-pause before claiming media protection; no token can unsend it. Serialize/reconcile per-player operations, and retain the original resume entitlement across transfer instead of rediscovering an already-paused player and losing it. — Basis: non-cancellable effect precedent [session.rs:985–1029](../../crates/shuvoice-app/src/session.rs#L985-L1029)
8. **Conservative restoration proposal:** snapshot only eligible currently-playing players, address operations by original unique bus owner plus object/interface, and keep per-player pause outcome. Resume only players this coordinator is entitled to restore; never broadcast play, never toggle, never start a replacement owner or previously idle player. Check capabilities/status/owner again and invalidate leases on observed conflicting user changes. Success, definitive failure, and timeout/unknown are distinct outcomes; a timeout must not trigger blind retries or blind Play. Reconcile status conservatively, acknowledging that generic external control cannot perfectly distinguish all user intent. No media title/URL metadata is needed. These are design requirements to validate against MPRIS/D-Bus research, not API behaviors proven here.
9. **Exit coverage and lifetime:** centralize ending/invalidation for pending stop, reset/recovery failure, ASR terminal disable/death, normal tail close, supersession, finalize cancellation, TTS takeover, and shutdown. Keep nonterminal ASR recovery within the same hold. Runtime must own a coordinator handle independently of Session so actor panic/forced abort can still request bounded restoration before tearing down the bus/runtime. Startup-abort cleanup must also join it. Drop may signal cleanup but cannot be the only async restoration path; SIGKILL/power loss cannot promise resumption. — Basis: [session.rs:585–626](../../crates/shuvoice-app/src/session.rs#L585-L626), [session.rs:1963–1997](../../crates/shuvoice-app/src/session.rs#L1963-L1997), [runtime.rs:276–340](../../crates/shuvoice-app/src/runtime.rs#L276-L340), [compose/mod.rs:766–807](../../crates/shuvoice-cli/src/compose/mod.rs#L766-L807)
10. **Scope:** add optional no-op-by-default media dependency to app/runtime; adapter + bounded coordinator transport in IO/composition; fake adapter in app tests; one explicitly approved core config setting and its schema/settings/docs/example coverage. Keep external media separate from ShuVoice TTS. Under recording-only scope it may resume while TTS starts after STT; extending the hold through TTS is a separate product choice. No shell hooks, control protocol changes, Python workers, or status observers are needed for the feature. — Basis: [traits.rs](../../crates/shuvoice-app/src/traits.rs), [session.rs:2030–2055](../../crates/shuvoice-app/src/session.rs#L2030-L2055), [AGENTS.md](../../AGENTS.md)

## 3. What verification has the highest value?

### Takeaway

**Proposal:** prioritize adversarial scheduling tests with a controllable fake media transport, then isolated-bus protocol tests. Existing tests already exercise slow reset, stop-tail retention, non-cancellable effects, and forced shutdown; extend those contracts rather than relying on a happy-path playback demo.

### Inferences

The following is a **proposed verification matrix**; none was executed in this source-only task.

- **Admission:** Start/StartAlt/Toggle/ToggleAlt share the same integration; duplicate, rearm-rejected, maintenance-rejected, dead-ASR starts issue no pause. Disabled recovery success acquires once; either reset failure restores once.
- **Pending cancellation:** Stop before any pause is sent; Stop after pause dispatch but before reply; successful ASR reset queued before Stop then B-start; completed start immediately stopped before first tick. Assert no stale transition to Listening, no dangling hold, and no spurious media Play.
- **Rapid generations:** A pause completes after A-stop/B-start; A release queued when B arrives; A Play already dispatched when B arrives; B's new pause fails. Assert per-player serialized reconciliation and honest readiness/degraded outcomes, with no forgotten original entitlement.
- **Actor responsiveness:** stall discovery, status read, pause, and resume independently. While stalled, Stop/status/maintenance rejection/shutdown must still progress; use existing control timing contracts and bounded whole-operation budgets, not an N-player times per-call timeout.
- **Audio boundaries:** inject distinct synthetic sample patterns before pause, during pending start, during recording, stop-edge wait behind a slow chunk, and grace. Assert the chosen preroll contract and that no samples captured after release enter the old utterance. Also exercise backend queued/partial chunks if clean-boundary changes are implemented.
- **Finalize variants:** silent/empty output, offline decode, streaming tail noise, remote commit success/failure/timeout, final injection stall/failure, superseding start, and TTS timeout. Media should release at capture closure regardless of transcript outcome or injection delay.
- **Error lifecycle:** nonterminal chunk errors retain hold; breaker opening and owner death terminate or close capture before release; start recovery failure restores; capture-fatal handling tested if added. No media failure increments ASR breaker or emits transcript/player metadata.
- **Player ownership:** multiple playing players with partial failures; already-paused/stopped players; missing CanPause/CanControl; disappearance and same-name replacement; user resumes/stops during recording; new player appears mid-recording; timeout after remote side effect. Assert only valid owned leases restore and no bus activation/new-player playback occurs.
- **Shutdown:** pending discovery/pause/resume and active hold under normal shutdown, startup abort, actor panic/forced abort, command-channel closure, disconnected session bus, and coordinator failure. Assert explicit bounded cleanup, no detached untracked late pause, and no false claim of successful restoration for unknown outcomes.
- **Test isolation / checks:** adapter contract tests should use a private test bus and fake player services, not the user's active session. Run app/core/IO tests and CLI feature-off/default checks once implemented, preserving event backpressure and current shutdown bounds. A later explicitly authorized real-player check can validate latency and behavior without collecting metadata.

### Gaps

- The source was inspected but not changed, compiled, or tested. Only this research note was added.
- Existing tests were inspected as coverage anchors, not run or certified passing. Platform integration and timing claims require future tests.
